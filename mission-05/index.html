Завантаження ZIP і перегляд демонстрації — різні дії. Для редагування коду потрібна розпакована папка.

Безпека: використовуйте вигадані імена. Замовлення навчальні, не надсилаються, платежів та бекенду немає. Уся робота NextLab зберігається локально у вашому браузері.

Виклик: розробник запевняє, що форма замовлення готова, але вона підтверджує некоректні дані. Досліди помилки, перш ніж писати код.

Це спеціально несправна демонстрація, не справжня форма. Вводь лише вигадані дані. Замовлення нікуди не надсилається.

Це навчальна копія форми їдальні: обери страву, введи дані та досліди, чому некоректне замовлення підтверджується. У справжньому стартовому застосунку ти виправлятимеш цю поведінку.

Некоректні значення не повинні призводити до успішного підтвердження; потрібно перевіряти ім’я після trim(), клас, цілу кількість 1–5 і показувати повідомлення біля поля.

Етап 02 · 15 хв

Як працює форма замовлення

Вивчи короткі блоки теорії, зокрема новий метод trim(). Усі акордеони спочатку закриті. Після цього виконай мініперевірку.

Що робить trim() і навіщо він потрібен?

trim() — метод рядка JavaScript. Він повертає новий рядок без пробільних символів на початку й наприкінці. Початковий рядок не змінюється. Пробіли між словами зберігаються. 

const name = "   Анна   ";
const cleanName = name.trim();
console.log(cleanName); // "Анна"
console.log("   ".trim()); // ""

Перевірка name.length >= 2 помилково прийме рядок із трьох пробілів. Тому спочатку виконай trim() , а потім перевір довжину очищеного рядка.

Спробуй у консолі: " Оля ".trim() , " ".trim() , "Анна Марія".trim() . Поясни результати.

Правила перевірки

Ім’я після trim() має містити щонайменше два символи. Клас має бути обраний із доступних значень. Кількість — ціле число 1–5. Коментар необов’язковий.

HTML і JavaScript

Атрибути required, min, max, step допомагають браузеру перевіряти поля. JavaScript додатково перевіряє бізнес-правила. Порожнє значення слід перевірити до Number(), адже Number('') дорівнює 0.

Події форми

input спрацьовує під час редагування, change — під час зміни вибраного значення, submit — при відправленні форми. preventDefault() запобігає звичайному надсиланню й перезавантаженню сторінки.

Стани інтерфейсу

Початковий → редагування → помилка або успіх. Після редагування даних попередній успіх має бути скинутий; підтвердження можливе лише після нової перевірки.

Доступність

Повідомлення про помилку розміщують біля поля та пов’язують через aria-describedby; aria-invalid позначає некоректне поле, aria-live сповіщає про зміну статусу. Не покладайся лише на колір.
