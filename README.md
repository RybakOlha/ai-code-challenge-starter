# AI Code Challenge · NextLab Starter v1.0

Еталонний стартовий репозиторій для 9 навчальних пар (11 клас). **Це каркас, а не готовий MVP.** Кожен учень створює власний продукт, зберігаючи спільний стек.

## Запуск
1. Відкрийте папку у VS Code.
2. Відкрийте термінал у корені проєкту.
3. Запустіть `python -m http.server 8000` (або `python3 -m http.server 8000`).
4. Відкрийте `http://localhost:8000`.
5. Натисніть **Перевірити JavaScript**. Не відкривайте сторінку через `file://` — використовуються ES Modules.
6. Зупинка сервера: `Ctrl+C`.

## Передумови
VS Code, браузер із DevTools, Python 3 для локального сервера, Git. Copilot Agent Mode — лише якщо є доступ і виконані вікові та організаційні умови. Для GitHub Pages Python не потрібен.

## Безпечний початок роботи з Git
Якщо завантажили ZIP, історії Git у ньому немає:
```bash
git init
git add .
git commit -m "chore: initial starter"
```
Потрібні налаштовані `user.name` і `user.email` (не використовуйте чужі дані). За потреби вчитель роздає готовий репозиторій.

## Структура
- `index.html`, `css/` — стартова сторінка й стилі
- `js/` — мінімальні ES-модулі; основна логіка ще не реалізована
- `docs/PRODUCT_BRIEF.md` — вимоги до власного MVP
- `docs/DECISIONS.md` — журнал рішень
- `docs/RELEASE_CHECKLIST.md` — перевірка перед релізом
- `tests/test-cases.md` — ручні тести
- `.github/copilot-instructions.md` — інструкції для агента
- `tools/smoke_check.py` — перевірка структури проєкту

## Послідовність місій
01 — вимоги; 02 — Git та контроль агента; 03 — інтерфейс; 04 — перша функція; 05 — дані; 06 — дефекти; 07 — доступність; 08 — реліз; 09 — захист.

## Межі MVP
2–3 логічні розділи; 2 змістовні функції; адаптивний інтерфейс; дані без бекенду; не менше 5 тестових сценаріїв; Git-історія та пояснення рішень.

## Важливо
Не вставляйте в промпти персональні дані, паролі чи токени. Не надавайте агенту автоматичне схвалення всіх команд. Для тестування користуйтеся вигаданими даними. Перед роботою з неповнолітніми перевірте вікові умови й доступність сервісу. Якщо агент недоступний, виконуйте ту саму задачу в редакторі вручну, зберігаючи протокол перевірки.

## Педагогічна примітка
Місії 01–09 НЕ реалізовані наперед. Учні самі визначають продукт і поступово розвивають каркас. `tools/smoke_check.py` перевіряє структуру, а не якість чи готовність MVP.
